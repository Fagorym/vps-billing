## Запуск нового пилота

Нужны установленный Proxmox VE 9, SSH root, исправный Python 3.12+ и доступ к интернету.
Параметры сервера заданы для `80.249.131.4`; перед запуском на другом сервере сверяйте inventory,
сетевые параметры, VMID, storage, конфигурацию биллинга и параметры публикации HTTPS.
Подробности и проверки — в README каждого проекта.

```sh
./proxmox-pilot/pilot up
./billing-pilot/billing up
./billing-pilot/billing publish
```

Панель текущего пилота: **https://80.249.131.4/admin**. Данные входа создаются локально в
`billing-pilot/.secrets/bootstrap.json` и не входят в репозиторий.

## Выдача VPS

1. Создать клиента и оформить VPS-заказ; для пароля оставить поле SSH-ключа пустым.
2. Подтвердить соответствующий счёт через **Mark as Paid → Submit**.
3. Адаптер создаст VM. В кабинете клиента появятся SSH-команда и кнопка начального пароля.
4. При первом SSH-входе клиент заменит начальный пароль своим. При заполненном SSH-поле вход остаётся по ключу.

Приостановка и возобновление управляют той же VM. Отмена останавливает VPS и сохраняет диск.
Повторная активация не создаёт вторую VM и не меняет пароль.

Оплаты работают в тестовом режиме; исходящие письма отключены. Уведомление ЮMoney пока
нужно сопоставлять со счётом вручную. Автоматической интеграции с ЮMoney нет.

## Обновление установленного пилота

```sh
./billing-pilot/billing update
```

Для управления текущим сервером из нового checkout перенесите свои локальные `.secrets` и `.state`
из обоих проектов, а также исходный `billing-pilot/.env` по защищённому локальному каналу.
Файл `.env` должен соответствовать `billing-pilot/.secrets/bootstrap.json`; не генерируйте
новые пароли для уже установленного биллинга. Генерация новых ключей не восстановит доступ
к существующим VM. Для нового сервера секреты создаются командами проекта.

Начальные пароли клиентов хранятся зашифрованными на Proxmox. Ключ
`/var/lib/safehost-billing/credential.key` нужно резервировать вместе с согласованной копией
`allocations.sqlite`; эти рабочие данные также не входят в исходники.

## Проверки

```sh
./proxmox-pilot/pilot validate
./billing-pilot/billing test
```

Проверка биллинга требует Docker и использует отдельный временный Compose project с FakePVE.
Это не проверка загрузки настоящего клиентского VPS; живой SSH проверяется отдельно.
PDF собирается `python billing-pilot/docs/build_manual.py`; нужны ReportLab и шрифты Arial
из стандартного каталога macOS, используемого в исходнике.

В репозитории нет лендоса, его обработчиков заявок, ключей, паролей, БД, журналов и виртуальных окружений.
