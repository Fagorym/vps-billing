# Бесплатный пилот биллинга VPS

FOSSBilling 0.8.8 + MariaDB + наш Custom product plugin `SafehostProxmox`.
Тестовые счета, без банковских карт и реальных списаний. Только штатный Custom gateway:
администратор подтверждает оплату и запускает обработку счёта. Внешние письма отключены
через штатный транспорт `null://null`.

## Установить на Selectel одной командой

```sh
cd '/Users/olegveber/Documents/ChatGPT/аренда/billing-pilot'
./billing up
```

При первом входе OpenSSH попросит проверить fingerprint сервера и ввести пароль root.
Пароль не сохраняется. Команда использует соседний проект `../proxmox-pilot`:
проверяет установленный Proxmox, настраивает NAT, создаёт шаблон 9000 и первый
тестовый VPS 102. Затем создаёт **VM 101** для биллинга:

| Что | Конфигурация |
|---|---|
| Proxmox | `pve1`, `80.249.131.4`, публичный bridge `vmbr0` |
| Биллинг | Ubuntu 24.04, 2 vCPU, 4 GiB RAM, 40 GiB, `10.10.10.11` |
| SSH биллинга | `80.249.131.4:2223`, `vpsadmin`, отдельный ключ |
| VPS по заказам | VMID 1100–1109, IP `10.10.10.20–29` |
| SSH VPS | `80.249.131.4:22220–22229`, `vpsadmin`, ключ или начальный пароль |
| Тарифы | Mini: 1/1/20 — 390 ₽; Small: 2/2/50 — 650 ₽; Medium: 4/4/80 — 1100 ₽ в месяц |

Нужно место на `local-lvm` для VM 101 и выбранных VPS; минимум 2 GiB RAM остаётся
хосту. Перед клонированием проверяется запас RAM и диска. Если VMID, IP или порт
занят чужим ресурсом, установка отказывается менять его. VM 100, созданная вручную,
не считается автоматически принадлежащей проекту: выбирайте свободный VMID
в `../proxmox-pilot/group_vars/proxmox.yml`, сохранив шаблон 9000.

Публичные IP, шлюз, NIC, SSH 22, панель 8006 и второй физический диск не меняются.
Биллинг не устанавливается в ОС гипервизора. На хост попадает только небольшой
Python адаптер и отдельный NAT service.

Опубликовать установленную панель на публичном IP с HTTPS:

```sh
./billing publish
```

Команда проверяет свободные порты 80/443, устанавливает nginx в VM 101, настраивает
отдельный NAT, получает сертификат на `80.249.131.4`, меняет URL FOSSBilling и
включает автопродление. Домен не требуется. Открывайте
**https://80.249.131.4/admin**. Сертификат живет около 6 дней, поэтому таймер продления
должен работать; порты 80 и 443 должны оставаться доступными. Сам контейнер по-прежнему
слушает только `127.0.0.1:8088` в VM, nginx передает запросы в него.

Проверка публикации и входа без изменения заказов:

```sh
../proxmox-pilot/.venv/bin/python public/check.py
```

`./billing open` остается вспомогательным SSH-туннелем; после публикации канонический
адрес FOSSBilling — публичный HTTPS, поэтому для браузера используйте адрес выше.

## Первый заказ и SSH

1. Зарегистрируйте тестового клиента в кабинете с адресом на существующем почтовом домене,
   закажите один из трёх VPS. FOSSBilling проверяет DNS домена; исходящие письма отключены.
2. Для входа по паролю оставьте поле **«Публичный SSH-ключ (необязательно)»** пустым.
   Для входа по ключу вставьте `ssh-ed25519` из файла `.pub`; пароль тогда не выдаётся.
3. В админке: **Invoicing → Invoices → счёт → Mark as paid**,
   transaction ID — уникальная строка `TEST-001`, затем **Submit**.
   Связанные задачи в установленной форме запускаются автоматически.
4. В Proxmox появится следующая свободная VM. Дождитесь cloud-init и guest agent.
   В кабинете клиента откройте услугу: адрес, порт, пользователь `vpsadmin` и команда SSH.
5. Для парольного VPS нажмите **«Показать начальный пароль»**. При первом SSH-входе
   введите его и задайте свой новый пароль. После смены сохранённый начальный пароль
   больше не работает; биллинг не знает новый пароль клиента.
6. Первый SSH fingerprint проверьте в консоли этой VM:
   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`.
7. Выполните команду из услуги, например `ssh -p 22221 vpsadmin@80.249.131.4`.
   Для VPS с ключом добавьте `-i ~/.ssh/id_ed25519`.

Если оформляете заказ за клиента: **Clients → клиент → Login to Client Area**,
закажите VPS с пустым SSH-полем. После поступления через ЮMoney подтверждайте
соответствующий счёт вручную. Автоматической интеграции с ЮMoney нет; письма отключены.

Пароль генерируется один раз на заказ и сохраняется на Proxmox в зашифрованном виде.
Обычный статус VPS и HTML страницы не содержат пароль: его запрашивает отдельная
кнопка владельца активной услуги. Повторы активации не сбрасывают пароль и не создают
второй VPS. На диске VM находится хеш; SSH под root отключён. Старые VM с ключами
сохраняют свой способ входа. Ключ выдачи паролей `/var/lib/safehost-billing/credential.key`
нужно резервировать вместе с `allocations.sqlite` и его WAL при наличии; без него
восстановить начальные пароли из БД нельзя. Для согласованной копии SQLite используйте
backup API или остановите операции адаптера на время копирования.

Обновить уже установленный пилот без повторной настройки хоста и создания VM:

```sh
./billing update
```

Обновляются адаптер, приложение и поле заказа; VM и NAT не перенастраиваются.
Активация подтверждает создание и запуск VM. Готовность гостевого SSH проверяется
отдельно после cloud-init. Пилот не обещает готовый SSH в момент отметки счёта.

Расширить уже установленный пул с 5 до 10 мест:

```sh
./billing expand
```

Команда меняет только число слотов и добавляет NAT для новых мест. До изменений
проверяются свободные VMID, IP и порты, принадлежность текущих правил и контрольная
сумма конфигурации. Согласованная копия SQLite, конфигурация, ключ выдачи паролей
при наличии и прежний NAT сохраняются в закрытом каталоге
`/var/lib/safehost-billing/backups/pool-5-to-10-*`. VM, заказы, баланс и веб-доступ
не перенастраиваются; повторный запуск не добавляет дубликаты правил.

При прерывании повторите ту же команду: журнал `pool-expansion.pending.json`
позволяет завершить миграцию. Не удаляйте журнал и не правьте `config.sha256`
вручную. Обычный `./billing up` сохраняет защиту от изменения установленного пула.
Миграция поддерживает только 5 → 10, дальнейшее расширение требует отдельной проверки.
Лимит 10 не отменяет проверку RAM и диска при выдаче VPS. Все десять мест рассчитаны
на небольшие нагрузки; крупные тарифы могут исчерпать RAM раньше.

## Приостановка, отмена, повторы

- Suspend останавливает VM и отключает запуск при перезагрузке Proxmox.
- Unsuspend запускает её и возвращает автозапуск.
- Cancel и Delete в биллинге **останавливают VM, сохраняют диск и резерв слота**.
  Удаление диска — отдельная ручная операция администратора после проверки.
- Отменённый слот не выдаётся новому клиенту. Автоматического Uncancel нет.
- Не создавайте новый заказ при сетевом сбое активации: повторите активацию того же заказа.
  Резервирование сохраняется до клонирования; потерянный ответ не создаёт второй VPS.
- Если оплата отмечена, но VPS не выдан, проверьте Failed invoice items и повторите
  задачу/активацию после устранения ошибки. Статус оплаченного счёта сам по себе
  не доказывает готовность VM.

## Доступ адаптера

В VM биллинга хранится отдельный ключ с `restrict`, `from=10.10.10.11` и forced command
на Proxmox. Через него нельзя получить shell, SFTP или туннель. Адаптер принимает только
create/status/password/suspend/unsuspend/cancel, проверяет order/client, тариф, публичный ключ,
метку владельца и принадлежность дисков выделенной VM. Команд `qm destroy` нет.
Ключ администратора Proxmox в контейнер биллинга не передаётся.

Состояние адаптера: `/var/lib/safehost-billing`, конфигурация — `/etc/safehost-billing/config.json`.
Приложение в VM: `/opt/billing-pilot`, Docker volumes проекта `safehost-billing`.
Перед дальнейшими изменениями сохраняйте БД FOSSBilling, volume приложения, состояние
адаптера и секреты вместе. Конфигурация уже созданного пула закреплена SHA256;
её изменение требует отдельной миграции.

Пилот использует общий private bridge и NAT. Для продажи независимых VPS дальше
нужны отдельная проверка сетевой изоляции, публичные IP, резервные копии и внешний
платёжный шлюз. Эти этапы не включены в тестовый режим.
