# Proxmox pilot

Настройка установленного Proxmox VE 9 на Selectel и первый Ubuntu VPS с SSH.

Сеть переведена 16 октября 2026: `45.9.88.50/28`, gateway `45.9.88.49`, VLAN 1348. Текущая эксплуатация и backup перехода — [PUBLIC-IPV4.md](../billing-pilot/PUBLIC-IPV4.md). `pilot up` — прежний bootstrap: маркер владения VM102 включает старый публичный IP, поэтому повторный запуск с новым профилем может остановиться на защите от изменения параметров. VM102 здесь не перенастраивалась; не заменять её marker вслепую.

Из папки `аренда`:

```bash
./proxmox-pilot/pilot up
```

Нужны интернет и исправный Python 3.12+ на Mac/Linux. Команда создаст локальное `.venv`, установит закреплённый Ansible и сгенерирует два отдельных SSH-ключа. При первом входе OpenSSH покажет fingerprint сервера и запросит пароль root. Сверьте fingerprint через консоль Proxmox (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`). Пароль вводится в терминал; проект его не сохраняет. Ключ хоста добавляется в `/root/.ssh/authorized_keys`. Остальные ключи пользователя сохраняются.

В этом рабочем окружении `.venv` уже подготовлено. Если системный Python неисправен, задайте `PILOT_PYTHON=/путь/к/python3.12`. Требования и установка находятся внутри проекта, без глобального `pip install`.

После успешной проверки:

```bash
./proxmox-pilot/pilot ssh
```

Это SSH на `45.9.88.50:2222` под `vpsadmin` с ключом `.secrets/vps_ed25519`. Пользователь имеет `sudo` без пароля. Парольный вход и root-вход в гостевую Ubuntu отключены. Настройки SSH самого Proxmox сохраняются.

## Что создаётся

| Ресурс | Параметры |
|---|---|
| Хост | `pve1`, `45.9.88.50`, существующий `vmbr0 → nic0` |
| Частная сеть | `vmbr1`, `10.10.10.1/24`, без физического порта |
| Шаблон | VM `9000`, Ubuntu 24.04 cloud image, OVMF / Q35 / VirtIO |
| VPS | VM `102`, `vps-test`, 1 vCPU / 2048 MiB / 20 GiB |
| IP VPS | `10.10.10.10/24`, gateway `10.10.10.1`, DNS `1.1.1.1` |
| NAT | Интернет через IP хоста; `45.9.88.50:2222 → 10.10.10.10:22` |

Параметры в `group_vars/proxmox.yml`, адрес SSH хоста — в `inventory.yml`.

Ansible отключает subscription-only PVE/Ceph sources, сохраняет Debian и существующие бесплатные repositories, при необходимости добавляет PVE no-subscription. Полный upgrade хоста и reboot не выполняются.

Private bridge добавляется отдельным отмеченным блоком в `/etc/network/interfaces`; поднимается только `vmbr1`. Старый `/etc/network/interfaces.d/vps-pilot` переносится в резервную копию **только при точном совпадении** с прежней ручной конфигурацией из этой сессии. Изменённый вручную файл вызывает остановку. NAT хранится в собственных цепочках `PILOT_*` и systemd-сервисе; остальные правила не очищаются. Настройка сохраняется после reboot, VPS включён в autostart (`onboot=1`).

Образ скачивается на Proxmox, проверяется по закреплённому SHA256, импортируется в `local-lvm` и превращается в шаблон. Полный clone получает отдельный диск. Cloud-init создаёт пользователя, ключ и статическую сеть, устанавливает QEMU guest agent. `local` получает дополнительный тип content `snippets`, остальные типы сохраняются.

В конце Ansible получает SSH host key гостя через аутентифицированный Proxmox и guest agent, закрепляет его локально, входит через публичный порт и проверяет cloud-init, SSH, guest agent, CPU/RAM и расширение корневой файловой системы. Успех выводится только после этих проверок. Первое выполнение зависит от скорости скачивания образа и Ubuntu packages.

## Повторный запуск и конфликты

```bash
./proxmox-pilot/pilot preflight
./proxmox-pilot/pilot validate
```

`preflight` проверяет сервер без изменения сети, storage и VM. При первом подключении он тоже добавляет ключ доступа root. `validate` запускает локальные тесты и Ansible syntax check; сервер не нужен.

Проверяются версия ОС/PVE, KVM, MAC/IP/gateway, pending `interfaces.new`, свободные ID/порт, storage и известные совпадения IP в cloud-init других VM. Проверка не обнаруживает произвольные вручную заданные IP внутри чужих гостей — такие адреса нужно учитывать отдельно.

VM/template получают маркер владельца и fingerprint параметров. Чужой VMID или изменение параметров/ключа вызывает остановку. Проект не удаляет VM, не уменьшает диски и не трогает `/dev/sdb`. Свои незавершённые template/clone можно продолжить повторным запуском, если нет lock. Не снимайте lock вслепую: сначала проверьте задачи Proxmox. Для уже запущенного VPS изменения конфигурации не применяются автоматически.

На текущем сервере VM `100` создана через GUI, поэтому проект использует свободный ID `102`; импорт и удаление чужой VM не предусмотрены. Если выбран другой ID, старый VPS остаётся, а для нового понадобятся отдельный IP и внешний порт. Этот проект рассчитан на **один** VPS; это не панель массового provisioning.

Сохраняйте `.secrets`: потеря гостевого ключа означает потерю текущего доступа. `.secrets`, `.state`, `.venv` исключены из Git. Приватные ключи не отправляются на сервер. Резервные копии сетевого файла лежат рядом с `/etc/network/interfaces`; прежний drop-in — `/var/lib/proxmox-pilot/backups/vps-pilot.manual`; APT-файлы получают отдельные backups.

При включённом PVE firewall предварительная проверка остановится: для него нужен отдельный согласованный набор forwarding/conntrack rules. Проект не отключает firewall. После переустановки Proxmox сверяйте новый SSH fingerprint через консоль прежде, чем менять `.state/known_hosts`.

Это пилот на одном диске, без RAID и внешних резервных копий. Продажа клиентам требует отдельной настройки изоляции, firewall, квот, backup и мониторинга.

## Проверка проекта

Локальные тесты проверяют отказ на чужом VMID, повторное использование ресурсов, восстановление после прерванного импорта/clone, запрет уменьшения диска, сохранность публичной сети и Debian repositories, содержимое cloud-init, область NAT-правил и разделение SSH-ключей хоста/гостя с учётом приоритета переменных Ansible. `validate` также выполняет настоящий Ansible-модуль на имитации `qm/pvesh`. Эти проверки не подтверждают загрузку настоящей VM. Живая проверка выполняется `pilot up` на вашем сервере.
